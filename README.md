# recipang

장바구니와 나의 냉장고에 담긴 식자재로 레시피를 추천받는 에이전트입니다. 기획은 [설계안.txt](설계안.txt)에 있습니다.

## 진행 상황

| 설계안 할 일 | 상태 | 파일 |
|---|---|---|
| 1. 식자재 세분화 | 완료 | `catalog.py` |
| 2. 장바구니 / 나의 냉장고 담기 | 완료 | `storage.py`, `app.py` |
| 3. 레시피 추천 (정형화된 레시피 DB) | 완료 | `recipe_db.py`, `app.py`, `data/recipes.json` |
| 4. 없는 재료 장바구니 담기 | 완료 | `app.py` |
| 5. 자연어 검색 + 장바구니·냉장고 대화 조작 | 진행 중 — 라우터, 레시피 검색, MCP 도구(담기·빼기·옮기기·조회), 단기 기억(최근 5턴), LangGraph 그래프로 전환까지 | `router.py`, `memory.py`, `handlers.py`, `graph.py`, `mcp_tool_server.py`, `rag_module.py`, `recipe_db.py`, `app.py` |

지금 실행할 수 있는 건 **Streamlit 화면(`app.py`)의 장보기와, 대화창의 레시피 추천·장바구니/냉장고 조작**입니다.

## 실행 방법

아래 명령은 모두 PowerShell에서 `recipang` 폴더(이 저장소의 루트)를 기준으로 실행합니다.

### 1. 가상환경 만들기 (처음 한 번만)

```powershell
py -3.13 -m venv venv
venv\Scripts\python -m pip install -r requirements.txt
```

- **Python 3.13으로 만드세요.** 임베딩에 쓰는 `fastembed`가 의존하는 `onnxruntime`은 Python 3.15용 설치 파일이 아직 없어서, 3.15로 만든 가상환경에서는 설치가 실패합니다(`Could not find a version that satisfies the requirement onnxruntime...`). 설치된 Python 목록은 `py -0p`로 확인할 수 있습니다.

- 자연어 검색에 Claude API를 쓰므로 `.env`에 API 키가 있어야 합니다. 없으면 `.env.example`을 `.env`로 복사하고 `ANTHROPIC_API_KEY=` 뒤에 키를 넣으세요. 키가 없거나 틀리면 대화창에 오류 안내가 나오고, 장보기와 [내 재료로 추천]은 그대로 동작합니다. `.env`는 `.gitignore`로 저장소에서 제외됩니다.

### 2. 앱 실행

```powershell
venv\Scripts\python -m streamlit run app.py
```

- 브라우저가 자동으로 열립니다. 열리지 않으면 http://localhost:8501 로 접속하세요.
- 처음 실행하면 터미널에서 이메일을 물어봅니다. 입력하지 않고 Enter를 누르면 됩니다.
- 종료하려면 터미널에서 `Ctrl + C`를 누릅니다.
- 대화창에 처음 요청할 때 장바구니·냉장고 도구 서버(MCP)를 띄우느라 10초 정도 더 걸립니다. 그 뒤로는 연결을 유지해서 빨라집니다.
- `graph.py`, `handlers.py`, `router.py`, `mcp_tool_server.py`를 고쳤다면 앱을 껐다가 다시 실행해야 반영됩니다 (에이전트를 앱 프로세스에 하나만 만들어 재사용하기 때문). 앱을 다시 시작하면 대화 기억도 사라집니다.

### 3. 사용법

본문은 왼쪽 **장보기**, 오른쪽 **레시피 추천**(대화창)으로 반반 나뉩니다. 화면이 좁으면 위아래로 쌓입니다. 장바구니와 나의 냉장고는 왼쪽 사이드바에 보이며, 나의 냉장고는 **식자재**와 **양념**(카탈로그의 '양념·오일' 대분류) 두 묶음으로 나눠 보입니다.

**장보기**
1. 대분류 탭(채소, 정육·가공육·달걀 등)을 고릅니다.
2. 담을 식자재를 체크합니다. 여러 탭을 오가며 골라도 체크가 유지되고, 고른 품목은 담기 버튼 위에 표시됩니다.
3. **[장바구니에 담기]** 또는 **[냉장고에 담기]**를 누릅니다.
4. 담긴 품목은 왼쪽 사이드바에 보이며, **[빼기]**로 하나씩 뺄 수 있습니다.

같은 품목은 장바구니와 냉장고 중 **한쪽에만** 담깁니다. 예를 들어 냉장고에 있는 달걀을 장바구니에 담으려고 하면 "나의 냉장고에 있어서 담지 않았습니다" 안내만 나오고 담기지 않습니다.

**대화창: 장바구니·냉장고 조작**

입력창에 장바구니나 냉장고에 대한 요청을 쓰면, **담기·빼기·옮기기는 바로 실행하지 않고 먼저 물어봅니다.**
- 답변에 "장바구니에 담을까요?" 같은 질문과 함께 바뀔 품목이 모두 체크된 상태로 나옵니다. 원하지 않는 품목은 체크를 풀고 **[담기]**(또는 [빼기], [옮기기])를 누르면 체크된 품목만 반영됩니다. **[취소]**를 누르면 아무것도 바뀌지 않습니다.
- 이미 그곳에 있거나 반대쪽에 있어서 바뀌지 않는 품목은 체크박스 위에 "제외했어요"로 안내합니다.
- **조회**는 바로 보여줍니다.
- 레시피 카드의 [+ 재료], 장보기의 담기 버튼, 사이드바의 [빼기]처럼 **직접 누르는 버튼은 지금처럼 바로 실행**됩니다.

| 작업 | 예시 |
|---|---|
| 담기 | "양념류는 다 냉장고에 넣어줘", "오징어볶음에 필요한 재료 장바구니에 다 넣어줘", "계란이랑 우유 장바구니에 담아줘" |
| 빼기 | "냉장고에서 설탕이랑 케첩 빼줘", "장바구니 비워줘" |
| 옮기기 | "장바구니에 있는 거 다 샀으니까 냉장고로 옮겨줘" |
| 조회 | "냉장고에 양념 뭐 있어?", "장바구니 보여줘" |

- 대분류("양념류", "채소")를 말하면 그 대분류의 식자재 전체, 레시피 이름을 말하면 그 레시피 재료 전체(양념 포함)가 대상입니다.
- '한쪽에만' 규칙은 그대로라서, 이미 냉장고에 있는 재료는 장바구니에 담지 않고 "나의 냉장고에 있어서 담지 않았어요"로 알려줍니다.
- 담기와 레시피 추천을 한 번에 말해도 됩니다 (예: "고추장 장바구니에 담고 매운 요리 추천해줘"). 추천은 바로 보여주고, 담기는 확인을 기다립니다. 그래서 추천은 담기 전 재료를 기준으로 합니다.

**대화창: 레시피 추천**
1. 입력창에 원하는 레시피를 자유롭게 씁니다. 예: "냉장고 재료로 만들 수 있는 매운 요리", "비 오는 날 먹을 얼큰한 국물 요리", "덜 자극적인 중식".
   - 에이전트가 요청을 검색 조건으로 해석하고(요리 종류·나라·조리법·맛·강도·상황 + 나머지 표현), 조건에 맞는 레시피를 찾아 짧은 설명과 함께 카드 3개를 보여줍니다. 한 번에 몇 초 걸립니다.
   - 답변 아래에 **해석한 조건**이 표시되니, 원하는 대로 해석됐는지 확인할 수 있습니다.
   - "냉장고 재료로", "있는 걸로"처럼 내 재료를 말하면 **양념까지 모두 갖고 있어 바로 만들 수 있는 레시피만** 찾습니다. 그런 레시피가 없으면 **담으면 좋은 재료**(하나만 담으면 조건에 맞는 레시피가 가장 많이 생기는 재료)를 [+ 재료] 버튼과 함께 알려줍니다.
2. 빠른 검색 **[내 재료로 추천]**을 누르면 AI를 거치지 않고 장바구니와 냉장고 재료로 바로 추천합니다(아래 정렬 규칙).
3. 답변 안의 **[더보기]**를 누를 때마다 그 답변에 3개씩 더 나옵니다.
4. 레시피 카드는 위에서부터 **재료 → 만드는 법 → 더 필요한 재료** 순서로 보입니다.
5. "더 필요한 재료"의 **[+ 재료]** 버튼을 누르면 그 재료가 바로 장바구니에 담깁니다. 이미 장바구니나 냉장고에 있는 재료는 **[✓ 재료]**로 표시되고 누를 수 없습니다.
6. 대화 기록은 새로고침하면 사라집니다.

**대화창: 이어서 말하기 (단기 기억)**

에이전트는 입력창으로 주고받은 **최근 5턴**(요청 1개 + 답변 1개 = 1턴)을 기억합니다. 그래서 앞 대화를 가리키는 말을 이어서 쓸 수 있습니다.

| 예시 | 기억에서 찾는 것 |
|---|---|
| "비 오는 날 먹을 얼큰한 국물 요리" → "그거 말고 덜 매운 걸로" | 앞에서 해석한 조건을 고쳐서 다시 검색 |
| "2번 레시피 재료 장바구니에 담아줘" | 앞 답변에 보여준 레시피 카드의 2번 |
| "방금 담은 거 다시 빼줘" | 앞에서 확인 후 실제로 담은 품목 |

- 기억하는 것: 입력창 요청과 답변(해석한 조건, 보여준 레시피 카드 3개, 장바구니·냉장고 안내), 확인 요청을 **[담기] 등으로 실행했는지 [취소]했는지**.
- 기억하지 않는 것: [내 재료로 추천] 결과, [+ 재료]·장보기 담기·사이드바 [빼기]처럼 직접 누른 버튼, [더보기]로 더 펼친 레시피.
- 5턴이 넘으면 가장 오래된 턴부터 잊습니다. 기억은 브라우저 세션마다 따로이고, 새로고침하면 대화 기록과 함께 사라집니다. 턴 수는 `memory.py`의 `WINDOW`로 바꿀 수 있습니다.

**대화창: 처리할 수 없는 요청**

| 상황 | 예시 | 답변 |
|---|---|---|
| 인사 | "안녕!", "고마워" | 인사하고 할 수 있는 일을 소개 |
| 할 수 없는 질문 | "오늘 날씨 어때?", "김치찌개 칼로리 얼마야?", "두부 얼마나 보관할 수 있어?" | 그 정보는 드릴 수 없다고 말하고 할 수 있는 일을 안내 (칼로리·보관 기간 같은 답은 하지 않음) |
| 알아들을 수 없는 입력 | "ㅁㄴㅇㄹ" | 다시 말해 달라고 하고 요청 예시를 보여줌 |
| 가리키는 대상이 불분명 | (앞 대화 없이) "그거 담아줘", (레시피 3개를 본 뒤) "그 레시피 재료 담아줘" | 아무것도 바꾸지 않고 무엇을 말하는지 되물음 |
| 카탈로그에 없는 품목 | "장바구니에 노트북 담아줘", "망고랑 양파 담아줘" | "식자재 카탈로그에 없는 품목이라 다룰 수 없어요: 망고"로 안내하고, 나머지 품목은 그대로 처리 |
| 검색이 반영할 수 없는 조건 | "우유로 만들 수 있는 요리", "10분 안에 만드는 매운 요리", "돼지고기 없이 만드는 찌개" | 특정 재료 포함·제외, 조리 시간, 칼로리, 인분처럼 레시피 DB에 없는 조건은 답변 아래 **검색에 반영하지 못한 조건**으로 표시합니다. 다른 조건(매운, 찌개 등)이 있으면 그 조건으로만 찾고 반영하지 못했다고 알려주며, 다른 조건이 없으면 검색하지 않고 찾을 수 있는 조건을 안내합니다. |

[내 재료로 추천]의 정렬 규칙:
- **더 필요한 재료(양념 포함)가 적은 순서**로 보여줍니다. 카드 제목의 "N개 더 필요"도 양념을 포함한 개수입니다.
- 개수가 같으면 그중 **양념이 아닌 재료(주재료·부재료)가 더 많이 필요한** 레시피가 먼저 나옵니다. 즉, 없는 양념이 적은 레시피가 앞입니다. 그래도 같으면 레시피 id 순서입니다.
- 카드의 "더 필요한 재료"에서 양념은 따로 구분하지 않고 맨 뒤쪽에 놓입니다.
- 내 재료를 하나도 쓰지 않는 레시피도 목록 뒤쪽에 포함됩니다.
- 답변마다 순서와 카드 내용은 **요청한 시점의 재료 기준**으로 유지됩니다(자연어 검색도 같음). 카드에서 재료를 담거나 사이드바에서 빼도 순서는 그대로이고, 버튼의 ✓ 표시만 바뀝니다. 바뀐 재료로 다시 추천받으려면 다시 요청하세요. 새 답변이 아래에 추가되고, 이전 답변은 그대로 남습니다.

## 데이터 저장 위치

- **장바구니 / 나의 냉장고:** `recipang.db`(SQLite). 앱을 처음 실행할 때 자동으로 생성되며, 테이블은 `cart`와 `fridge`입니다. 모두 비우려면 앱을 종료한 뒤 `recipang.db`를 삭제하세요.
- **레시피:** 원본은 `data/recipes.json`이고, 앱은 여기서 만든 `recipes.db`(테이블 `recipes`, `recipe_tastes`, `recipe_tags`, `recipe_ingredients`, `recipe_steps`)를 씁니다. `recipes.db`가 없으면 자동으로 만들어집니다.
  - 레시피마다 속성이 붙어 있습니다: 요리 종류, 나라(한식/양식/중식/일식), 조리법(대표 1개), 맛 태그(매콤/짭짤/달콤/새콤/고소/담백, 여러 개), 강도(0 담백 ~ 3 자극적), 상황 태그(국물/밥반찬/한그릇/술안주 등, 여러 개). 값 목록은 `recipe_db.py` 맨 위 설명에 있습니다.
- **레시피 벡터 색인:** `local_qdrant/`(Qdrant 로컬, 컬렉션 `recipes`). 레시피 1개를 짧은 검색용 문서 1개로 만들어 임베딩합니다(`rag_module.recipe_document()`).
- `data/recipes.json`을 고쳤다면 `venv\Scripts\python recipe_db.py`(또는 `recipes.db` 삭제)와 `venv\Scripts\python rag_module.py`를 실행해야 반영됩니다.

## 모듈 단독 실행

화면 없이 모듈만 확인할 때 씁니다.

```powershell
venv\Scripts\python catalog.py   # 대분류별 식자재 목록 출력
venv\Scripts\python storage.py   # 임시 DB로 담기/빼기 데모 (recipang.db는 건드리지 않음)
venv\Scripts\python recipe_db.py # recipes.db를 새로 만들고 예시 재료로 추천 상위 10개 출력
venv\Scripts\python rag_module.py # 벡터 색인을 새로 만들고 의미 검색 / 레시피 검색(retrieve) 예시 출력
venv\Scripts\python memory.py     # 단기 기억 데모 (5턴 창에 6턴을 넣어 가장 오래된 턴이 밀려나는지, 확인 결과 반영, 기억 요약 출력)
venv\Scripts\python router.py     # 예시 질문 분류 결과 출력 (API 키 필요)
venv\Scripts\python graph.py      # 그래프 구조(Mermaid) 출력 후 터미널 대화 (API 키 필요, 확인 대기는 y/N)
```

### LangGraph 그래프 (`graph.py`)

대화창 요청은 LangGraph `StateGraph`로 만든 그래프가 처리합니다. 그래프는 흐름 제어(분기, 확인 대기에서 멈췄다가 재개, 대화 기억 저장)만 맡고, 요청 해석·검색·MCP 도구 호출은 `handlers.py`의 함수를 부릅니다.

```
START → route ─┬─(냉장고·장바구니)→ storage ─┬─(레시피도)→ recipe ─┐
               ├─(레시피만)──────────────────┼────────────→ recipe ─┤
               └─(둘 다 아님)────────────────┴──────────────────────┤
                                                                    ▼
                                                                 respond   ← 답변 정리 + 이번 턴을 기억에 기록
                                                                    │
                                 (확인 대기 작업 있음) → approval ⏸ → execute → END
                                 (없음) ──────────────────────────────────────→ END
```

- **확인 후 실행:** 담기·빼기·옮기기가 있으면 `approval` 노드가 `interrupt()`로 그래프를 멈춥니다. 화면에서 [담기]를 누르면 체크한 품목으로 그래프를 재개(`Command(resume=...)`)해 `execute` 노드가 실행하고, [취소]면 아무것도 바꾸지 않습니다. 확인하지 않고 새 요청을 보내면 그 작업은 '넘어감'으로 닫힙니다.
- **단기 기억:** State의 `turns`(최근 5턴)를 체크포인터가 대화방(`thread_id`, 브라우저 세션마다 하나)별로 저장합니다. 확인 결과(실행됨 / 취소됨 / 넘어감)도 그 턴에 반영됩니다. 체크포인터는 메모리 저장소(`InMemorySaver`)라 앱을 다시 시작하면 사라집니다.

**LangGraph Studio로 보기 (선택):** 그래프 그림과 노드별 State를 브라우저에서 보며 실행할 수 있습니다.

```powershell
venv\Scripts\python -m pip install "langgraph-cli[inmem]"
venv\Scripts\langgraph dev
```

- `langgraph.json`이 `studio.py`의 `graph`를 불러옵니다. 입력 칸에 `{"query": "매운 볶음 요리 추천해줘"}`처럼 넣습니다.
- 확인 대기에서 멈추면 resume 값으로 `true`(모두 실행), `{"chosen": [["쌀"]]}`(작업마다 실행할 품목), `false`(취소)를 넣습니다.
- Streamlit 앱과 동시에 실행하면 로컬 Qdrant 폴더 잠금 오류가 날 수 있습니다.

레시피 검색(`rag_module.retrieve`)은 질문을 **속성 조건**(`recipe_db.RecipeFilter`: 요리 종류·나라·조리법·맛 태그·강도·상황 태그)과 **나머지 표현**(text)으로 나눠 받습니다. SQL로 먼저 거르고(Q1이면 양념까지 모두 갖고 있어 만들 수 있는 것만), 그 안에서 text와 의미가 가까운 순으로 정렬합니다. Q1인데 만들 수 있는 레시피가 없으면, 담았을 때 조건에 맞는 레시피가 가장 많이 생기는 재료를 추천합니다.

`rag_module.py`는 `fastembed`와 `qdrant-client`가 필요합니다(`pip install -r requirements.txt`). 처음 실행할 때 임베딩 모델(약 0.22GB)을 내려받습니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `catalog.py` | 식자재 카탈로그 (대분류 → 식자재). 마켓컬리 식품 카테고리를 참고했습니다. |
| `storage.py` | 장바구니 / 나의 냉장고 SQLite 저장소 (담기, 빼기, 목록) |
| `recipe_db.py` | 레시피 DB(`recipes.db`) 생성과 추천 조회 |
| `app.py` | Streamlit 화면 (장보기, 레시피 추천) |
| `data/recipes.json` | 레시피 200개와 속성 (Claude가 생성, 재료는 모두 카탈로그 안의 것) |
| `rag_module.py` | 레시피 벡터 색인(`local_qdrant/`) 생성, 의미 검색, 레시피 검색(`retrieve`: SQL 거르기 → 벡터 정렬) |
| `router.py` | 라우터 — 레시피 검색 / 냉장고 / 장바구니 중 무엇이 필요한지 분류하고, 어느 것도 아니면 바로 답할 문장을 만듦 (Claude Haiku 5.5) |
| `memory.py` | 단기 기억 — 한 턴의 형식(요청·답변·해석한 조건·보여준 레시피·확인 결과), 최근 N턴을 남기는 State reducer, 프롬프트에 넣을 요약 텍스트 |
| `handlers.py` | 요청 처리 — 냉장고·장바구니 요청 해석과 작업 계획(LLM) → 확인한 작업 실행(MCP 도구), 레시피 요청 해석(LLM) → `rag_module.retrieve` → 설명 문장(LLM) |
| `graph.py` | LangGraph 그래프 — 노드·조건부 엣지로 흐름을 정하고, 확인 단계(interrupt)와 대화 기억(체크포인터)을 관리. `app.py`가 이것을 씀 |
| `studio.py`, `langgraph.json` | LangGraph Studio(`langgraph dev`) 진입점 |
| `mcp_tool_server.py` | MCP 도구 서버 — `storage.py`를 감싼 `list_items` / `add_items` / `remove_items` / `move_items` |
| `설계안.txt` | 기획 메모와 할 일 목록 |
| `.env.example` | API 키 예시. `.env`로 복사해 사용합니다. |

동작을 확인한 환경: Windows, Python 3.13, Streamlit 1.66.1
